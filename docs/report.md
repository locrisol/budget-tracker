# Personal Budget Tracker Project Report

## Introduction and Research

The Personal Budget Tracker emerged from research into the financial challenges faced by individuals who juggle multiple income sources and recurring expenses without a reliable way to monitor them. Informal surveys among peers and review of academic literature on financial literacy revealed that many people rely on ad‑hoc spreadsheets or simple notebook entries. While those methods provide a rudimentary overview, they fall short when categorizing transactions, generating summaries, or visualizing trends. Contemporary budgeting applications such as Mint, YNAB, and PocketGuard offer powerful functionality, yet they often require connecting to bank accounts, introduce recurring subscription costs, or present overwhelming interfaces for newcomers. The research phase therefore focused on bridging the gap between complex professional tools and minimal personal tracking methods. The goal was to design a lightweight, privacy‑respecting, and self‑hosted solution using open source technologies.

Throughout the research, emphasis was placed on accessibility and data ownership. By relying on local storage via SQLite and providing a simple Express.js server, the project ensures that users retain control over their financial records. Academic articles on personal finance management recommended clear categorization, regular review, and visual feedback as best practices for budgeting. These principles directly influenced the application's features. Moreover, the project studied usability heuristics to keep the interface approachable. Components like navigation layout, table listings, and form validation were inspired by common design patterns observed in well‑reviewed budgeting tools. This early research phase set a foundation for balancing functionality with simplicity, establishing the direction for subsequent development efforts.

## Objectives

The project pursued several key objectives. First, it aimed to provide a straightforward interface where users can log income and expenses without the friction of creating accounts or connecting external services. Second, it sought to categorize each transaction, enabling meaningful aggregation and comparisons across types of spending. Third, the tracker endeavored to compute and present real‑time summaries such as total income, total expenses, and the resulting net balance. A final objective was to incorporate visualizations that transform raw numbers into intuitive graphics, thereby reinforcing spending awareness.

Another vital objective centered on maintainability and extensibility. The codebase was structured so that future developers—or the original author at a later time—could easily add authentication, import/export features, or more advanced analytics. The use of popular libraries like Sequelize for database interactions and Nunjucks for templating reflects this forward‑looking mindset. The objectives also included adherence to security best practices, such as employing Helmet for HTTP headers and Morgan for detailed request logging. By meeting these objectives, the project would offer a reliable foundation for personal financial management while remaining accessible to learners who wish to explore full‑stack JavaScript development.

## Development Process

Development began by scaffolding an Express application and integrating Nunjucks to render server‑side templates. Early commits focused on establishing a cohesive layout using Bootswatch's Lux theme, which provides a clean aesthetic suitable for a finance application. The navigation bar was designed to surface the dashboard, transaction list, transaction form, and category management pages. Once the skeleton of the interface was complete, effort shifted to defining the data model.

Sequelize and SQLite were chosen for their minimal configuration overhead. Two primary models—`Category` and `Transaction`—capture the core data entities. Each transaction stores an amount, date, description, type (income or expense), and associated category. Relationships were defined so that categories have many transactions, and each transaction belongs to a single category. After initializing the database schema, the project implemented CRUD routes for transactions and categories. Routes handle operations such as listing transactions with optional filters, rendering forms for creation or editing, and performing deletion. Client input is validated at the model level by specifying non‑null constraints and enumeration of the transaction type.

With data persistence in place, development progressed to computing aggregate summaries for the dashboard. The application calculates total income and total expenses using Sequelize's `sum` function and presents recent transactions in a concise table. A summary API endpoint provides grouped totals by category, returning JSON data consumed by a Chart.js visualization. During development, nodemon facilitated rapid feedback, automatically restarting the server after changes. Middleware like body‑parser, Morgan, and Helmet ensured robust request handling, logging, and basic security hardening. Each feature was iteratively tested through the browser interface, validating data retrieval, input handling, and user feedback messages.

## Technologies Used

The project leverages a modern JavaScript stack tailored for simplicity and educational value. **Node.js** serves as the runtime environment, enabling the use of JavaScript on the server. **Express.js** provides a minimal yet powerful framework for routing and middleware, forming the backbone of HTTP request handling. To render dynamic HTML views, the application uses **Nunjucks**, a logic‑enabled templating engine that keeps presentation logic tidy while supporting template inheritance through files such as `layout.njk` and `dashboard.njk`.

For persistence, the tracker employs **SQLite** via **Sequelize**, an Object‑Relational Mapping (ORM) library that abstracts raw SQL queries into model methods. SQLite's file‑based database suits small‑scale personal applications and requires little configuration. **Chart.js** powers client‑side visualization, turning API responses into bar charts that display spending by category. On the styling front, **Bootswatch**'s Lux theme customizes **Bootstrap 5**, delivering responsive components with minimal effort. Additional dependencies include **Helmet** for security headers, **Morgan** for logging, **body‑parser** for form submissions, and **dotenv** to manage configuration through environment variables.

The development environment uses **Nodemon** and **Cross‑Env** to streamline testing across platforms. **Sequelize CLI** scripts support migrations, although the current project primarily relies on `sequelize.sync()` during bootstrap. Together, these technologies strike a balance between usability and extensibility. They are widely documented, open source, and familiar to many web developers, making the project accessible and easy to hand off for future enhancements.

## Advantages and Disadvantages

A primary advantage of the Personal Budget Tracker is its **privacy‑first design**. All financial data remains on the user's machine, removing concerns about third‑party data collection or breaches. The project's modest footprint also means it can run on low‑resource hardware such as single‑board computers or old laptops. Another benefit lies in the **transparent codebase**: developers or curious users can audit the application, modify components, or extend functionality without navigating proprietary systems. Furthermore, leveraging standard tools like Express and SQLite ensures long‑term maintainability and a shallow learning curve.

However, the project has notable trade‑offs. The absence of multi‑user support and authentication restricts its use to local environments or trusted networks. Without integration to banks or financial APIs, users must manually input every transaction, which can be time‑consuming. While SQLite is convenient, it may not scale for heavier workloads or concurrent access. The visualization components rely on client‑side rendering, which, although sufficient for modest datasets, may become unwieldy as the transaction count grows. Additionally, the current implementation lacks automated tests; reliability depends on manual verification, which could hinder collaborative development or deployment in production environments.

## Project Milestones

The project evolved through several milestones. **Milestone 1** established the basic Express application with Nunjucks templates and a navigation layout. This phase ensured that the core pages rendered correctly and that the application structure allowed for future expansion. **Milestone 2** introduced data persistence with Sequelize models for categories and transactions, enabling CRUD operations. Once users could create and manage entries, **Milestone 3** focused on building the dashboard: calculating aggregate sums, listing recent transactions, and presenting a net balance.

**Milestone 4** delivered filtering and search capabilities for the transaction list. Users can specify transaction type, category, and date ranges to narrow results. This feature required constructing dynamic Sequelize `where` clauses based on query parameters. **Milestone 5** implemented the API endpoint `/api/summary/by-category`, allowing the front‑end to fetch summarized data for visualizations. The final milestone integrated Chart.js, turning the API data into an interactive chart displayed on the dashboard. Each milestone built upon the previous one, gradually transforming a static template into a functioning budgeting tool. Future milestones could include authentication, recurring transactions, data export, or integration with external financial APIs.

## Individual Contributions

This project was conceived and developed as a **solo initiative**. The developer was responsible for end‑to‑end execution, encompassing research, design, coding, and testing. Tasks included defining the database schema, setting up the Express server, crafting Nunjucks views, and integrating Chart.js for visual feedback. The developer also configured middleware for security and logging, wrote seed scripts to populate sample data, and documented the project's setup through package scripts and environment variables.

Beyond coding, the developer conducted comparative research into existing budgeting tools, gathering insights on usability and feature sets. This research informed decisions such as emphasizing local storage over cloud syncing and prioritizing straightforward navigation. The solo nature of the project offered a comprehensive learning experience, reinforcing skills across front‑end templating, back‑end logic, and data modeling. Future contributions from collaborators could introduce automated testing, continuous integration pipelines, or new modules such as budgeting goals and alerts. Nonetheless, the current codebase reflects the cohesive vision and effort of a single contributor.

## Conclusion

The Personal Budget Tracker showcases how a focused set of technologies can deliver a practical solution for managing everyday finances. Through Express, Sequelize, Nunjucks, and Chart.js, the application supports essential budgeting tasks while remaining accessible and transparent.
